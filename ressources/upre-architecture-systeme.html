UPRE — du dépôt d'actif à l'opportunité qualifiée

Une seule chaîne, quatre couches imbriquées : un pipeline actif qui transforme une fiche commerciale brute en passeport exploitable, un pipeline intention qui qualifie ce qu'exprime un acquéreur, une couche de passeport & accès qui filtre ce qui est montré à qui, et une mémoire persistante qui empêche l'actif de repartir de zéro. Conçu pour être chiffré et construit en interne — sans plaquer une solution prête à l'emploi.

Le rez-de-chaussée, en détail — tâches 1 à 4

Le seul périmètre que ce build engage en premier. Tout le reste de l'immeuble attend que cet étage tienne.

01

Ingestion

Classe chaque document, rattache au bon actif par n° de mandat, déduplique.

02

Extraction

~80 champs normalisés contre un schéma unique — prix, typologie, DPE, surfaces, copropriété.

03

Score

Mesure la complétude réelle, décide : AIF direct / complément oral / entretien / non traitable.

04

AIF

Fiche de Valeur versionnée — distingue documenté, déduit, déclaratif, à vérifier.

↻ Si le score juge la matière insuffisante, l'étape 3 renvoie vers l'enrichissement vocal mandataire (tâche 3) — qui ré-injecte des données et redéclenche le score, plutôt que d'avancer une fiche incomplète.

Stack technique, couche par couche

Choisie pour 300 actifs et un opérateur, pas pour une promesse de scale. Chaque non-choix est volontaire.

extraction

Moteur de lecture

LLM vision (API)
Lit R1, jauges DPE, plans — extraction contre le schéma. Le choix de fournisseur se fait sur le taux d'exactitude mesuré en Phase 0, pas sur la marque.
pré-traitement

Documents

PyMuPDF / pdf2image
Rasterise les pages PDF avant envoi au modèle, conserve le nom de fichier comme source.
orchestration

Pipeline

Python — machine à états
Boucles et branchements explicites. Une lib comme LangGraph peut formaliser les états si utile.
Pas de framework d'agents lourd — 300 actifs ne le justifient pas.
stockage

Master & mémoire

PostgreSQL + pgvector
Tient le master, l'AIF versionné, et la similarité (déduplication, matching futur) via une extension, pas un service à part.
Pas de base graphe dédiée (Neo4j) — complexité prématurée à cette échelle.
coffre fichiers

Documents bruts

Stockage objet S3-compatible — France
Scaleway / OVH. Argument RGPD direct, pas une clause de devis à formaliser plus tard.
vocal

Enrichissement mandataire

Whisper (self-hébergé)
Transcription FR fiable, qualifiée « déclaration orale mandataire » avant ré-injection au score.
interface

Revue opérateur

Next.js / React
Revue, correction, gates de validation humaine — la supervision exigée à chaque étape sensible.
évaluation

Harnais de test

Script Python — diff champ à champ
Compare extraction vs vérité terrain sur 20–30 R1. C'est le livrable de la Phase 0.

Sélection des modèles — par rôle, pas par défaut

Pas un seul LLM partout. Chaque étage du pipeline a un profil de difficulté différent — la Phase 0 compare plusieurs candidats sur les mêmes R1 avant de fixer un choix.

étage 0

Classification

Modèle léger / rapide
Identifier « R1 » / « DPE » / « plan » est peu ambigu — pas besoin du modèle le plus cher pour trier des documents.
étage 1

Extraction de champs

Modèle vision le plus capable — à départager en Phase 0
Prix, DPE, surfaces ne tolèrent pas l'approximation. C'est l'étage où le taux d'exactitude mesuré sur 20–30 R1 tranche entre les candidats — pas une préférence de marque.
étage 2

Transcription vocale

Whisper (self-hébergé)
Sort du débat entre LLM généralistes — c'est un rôle de transcription dédié, pas un rôle de raisonnement.
étage 3

Synthèse & rédaction

Modèle léger ou intermédiaire
Une fois les champs propres, rédiger l'AIF ou la Note d'Actif converge en qualité entre modèles — le gain d'un modèle premium devient marginal.
étage 4

Gate + Fit + Match

Modèle haut de gamme
Comparer une intention à un actif et justifier un Go / No Go est un jugement nuancé, pas une extraction factuelle — la capacité de raisonnement redevient déterminante.
Escalade conditionnelle recommandée : modèle léger en première passe, escalade vers le modèle fort seulement si le score de confiance est bas.
↻ Le harnais de la Phase 0 doit être agnostique du fournisseur dès le départ — une couche d'abstraction simple (extract(document, model_id)) plutôt qu'un appel câblé à une seule API, pour comparer plusieurs candidats sur le même jeu de test et changer de modèle sans réécrire le pipeline.

Auto-incrémentation

Trois boucles distinctes qui écrivent dans le même sous-sol — aucune ne remplace les deux autres.

boucle courte

Donnée actif

Chaque document, réponse mandataire ou correction crée une nouvelle version de l'AIF — jamais un écrasement. Le score se recalcule à chaque version.

boucle moyenne

Donnée relationnelle

Chaque Match, objection, visite enrichit le profil actif et acquéreur. Le Fit devient plus précis avec l'historique — par retrieval sur le graphe, pas par fine-tuning.

boucle longue

Corpus mandataire

Les questions posées et réponses obtenues affinent le gabarit de questions pour les actifs suivants du même mandataire ou de la même typologie.

Évaluation

Le différenciateur face à Substi : eux promettent, ce système mesure — avant l'engagement, puis en continu.

ponctuelle — Phase 0

Avant tout engagement de build

  • 20–30 vraies R1 avec vérité terrain saisie à la main
  • Comparaison champ par champ : prix, typologie, DPE, surfaces
  • Sortie : un taux d'exactitude — le seuil d'acceptation contractuel
continue — en production

Jamais proposée par Substi dans le devis

  • Dérive d'extraction — ré-évaluation périodique sur le même jeu fixe
  • Décisions correctes — combien de « AIF direct » tiennent sans correction
  • Match utile — combien de Go aboutissent à une visite ou un NDA signé

Hypercare — à chaque mise en production

S'applique après la release de chaque phase, pas seulement à la fin du projet — la Phase 0 a son hypercare, le MVP a le sien, et ainsi de suite.

Semaine 1

Point quotidien

Feedback instantané sur les premiers cas réels, ajustements rapides du pipeline ou des prompts.

Semaine 2+

Point hebdomadaire

Surveillance plus large, suivi des métriques de la couche Évaluation, espacement progressif.

↻ Répété à chaque phase : Phase 0 → hypercare propre, Phase 1 (MVP) → hypercare propre, Phase 2 et 3 de même. Le rythme ne se relâche qu'après la semaine 1 de chaque release, jamais avant.

Structure tarifaire retenue

Un point d'entrée aligné sur le marché, sans prix fixe qui absorbe le risque de dépassement à ta place.

Le mensuel finance du développement actif, pas de l'exploitation. Pas de date butoir fixe : si le build glisse, le mensuel continue plutôt que d'être absorbé gratuitement.

2 500 €HT/mois · 3–4 mois visés
